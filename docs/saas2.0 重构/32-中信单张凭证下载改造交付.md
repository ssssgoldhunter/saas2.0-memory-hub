# 32-中信单张凭证下载改造交付

> 2026-09-03 交付。改造内容：单张凭证下载（bizFunc=02）从"调用方传三要素"改为
> **front 按 frontSsn + capability 自查定位银行凭证要素**，新增充值（RECHARGE，
> 05 转账入金）与 TI（清分入金，03）两条非渠道表定位链路，web-test 测试页同步。
> 代码位于 `cateringsass`（工作区，**未提交**，基线 `limeng_front@e3e21604` 之后）。

## 1. 背景与约束

- 原契约：调用方（consume）先查交易流水，把 bankSsn/bankTransDt/transType 三要素传给 front；
  front 只做银行通信。
- 新约束：调用方只给 header 必要参数 + frontSsn（+ 能力差异 specialData）；
  所有组装数据 front 自查；tenantId 走现有租户插件 + `TenantDataSourceShardingAlgorithm`
  分库路由；只改中信单张凭证下载，不动平安与其余 7 个文件端点。

## 2. 对外契约（`CiticReceiptDownloadReq`）

| 能力 | frontSsn | specialData | 定位链路 | TRANS_TYPE |
|------|----------|-------------|----------|------------|
| TRANSFER / CONSUME | 必填 | 不需要 | 渠道表（tenant_id+front_ssn，仅 SUCCESS） | 06 联机支付 |
| REFUND | 必填 | 不需要 | 渠道表 | 07 联机退款 |
| WITHDRAW | 必填 | 不需要 | 渠道表 | 04 智能提现 |
| PLATFORM_PAY / PLATFORM_RECEIVE | 必填 | 不需要 | 渠道表 | 12 / 13 |
| RECHARGE（充值C） | **不传** | `bizOrderNo`（充值表 transNo） | 中信通知表 `trans_platform_notify_zx`（frsc_senum） | 05 转账入金 |
| TI（清分入金） | **不传** | `acctNo` / `transDt`(yyyyMMdd) / `bizOrderNo` | 中信 24 接口（登记簿明细，翻页比对） | 03 清分入金 |

应答：`R<CiticReceiptDownloadRes>`（fileName + fileContent Base64，MSG 模式）；
银行未返回 FILE_NAME 时兜底 `{bankSsn}.pdf`。

## 3. 三条定位链路（`CiticReceiptElementLocator#locate` 全能力唯一路由）

1. **渠道表**（六能力）：`tenant_id + front_ssn + front_status=SUCCESS` 查对应
   `front_citic_*_transaction`，取 `bank_user_ssn` / `bank_trans_date`；未命中回查一次区分
   "交易不存在"（F300002）与"非成功状态"（F300003）；要素缺失报 F300003。
2. **充值通知表**：`tenant_id + frsc_senum = specialData.bizOrderNo` 查
   `trans_platform_notify_zx`，`notify_ssn` 即 bankSsn、`trans_dt` 即 bankTransDt；
   不做渠道状态校验（该表无渠道行）。front 侧新增只读实体
   `FrontTransPlatformNotifyZx` + Mapper（仅声明定位所需 6 字段，写入仍归 consume 通知链路）。
   不加 platform_code 条件（该表即中信专属）。
3. **TI 24 接口**（`CiticFileProcessChannel#locateTiBankSsn`）：组报文调 query-trans-details
   （bizFunc=24，acctNo SM2 加密，reserve TRANS_DATE/TRANS_TYPE=98/PAGE），
   **逐页查询比对，命中明细行 `TRANS_TYPE=JJ02` 且 `MCHNT_ORDER_ID=bizOrderNo` 即停**；
   最大页数以应答 `TOTAL_PAGE` 为准（未自设上限）；命中行 `REQ_JRN` 即 bankSsn，
   bankTransDt 取请求 transDt。未命中报"未查询到清分入金明细"（F300002）；
   命中行缺 REQ_JRN 报 F400003；账号日志仅保留末 4 位。

## 6. UAT 验证与后续修复（2026-09-03 收口）

### 6.1 银行应答键大小写差异（重要事实）

同属钱包应答，**键大小写按接口不同**（UAT 实测）：

| 接口 | 银行流水键 | 交易日期/时间键 |
|---|---|---|
| 27 转账 / 26 提现 / 23 退款 | `USER_SSN`（26 提现**无此键**，流水在 `queryId` 返回） | `USER_TRANS_DT` / `USER_TRANS_TM` |
| 2041 平台付款 / 2042 平台收款 | `userSsn`（驼峰） | `userTransDt` / `userTransTm` |
| 74 交易状态查询应答 | `USER_SSN` | `TRANS_DATE` / `TRANS_TIME` |

因此新增 `CiticTransferContractKeys.BANK_WIRE_USER_SSN/TRANS_DATE/TRANS_TIME`（驼峰，仅用于
2041/2042 钱包应答解析）；27/26/23 维持大写 `RESPONSE_*` 读取。此前六能力统一读大写键导致
2041/2042 落库 `bank_user_ssn`/`bank_trans_date` 恒为空（潜伏 bug，凭证下载为首个消费方）。
**对外 specialData 契约键（USER_SSN 等大写，见 06 号字段契约）不变。**

### 6.2 提现凭证补号（26 提现应答无 USER_SSN 键）

按"提现下载先查渠道行 bank_user_ssn，缺失则调 74 状态查询取流水、先回填渠道行再下载"落地：

- `CiticFileProcessChannel#locateWithdrawBankSsnByStatusQuery`：专用 74 查询
  （acctNo SM2 加密、reserve 仅 BUSS_ID、顶层 oriTransDate——与交易状态查询 WITHDRAW 分支报文一致）；
- `CiticReceiptElementLocator` WITHDRAW 分支：行内 bank_user_ssn 缺失 → 补号入参全部取自渠道行
  （acctNo=withdraw_account_id、transDate=bank_trans_date、bizOrderNo，无需调用方传）→
  74 查询 → 回填渠道行 → 用流水下载；补号要素缺失/74 无 USER_SSN 分别报 F300003。

### 6.3 失败应答带错误码

`receiptDownload` 失败应答 msg 统一带 Front 错误码前缀（如 `[F300002] 渠道交易不存在: ...`），
仅此端点；测试与调用方可直接展示错误码。
