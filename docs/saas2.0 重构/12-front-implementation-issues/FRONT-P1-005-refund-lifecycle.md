# FRONT-P1-005 退款原交易、累计金额和并发控制未闭环

- 状态：OPEN
- 优先级：P1
- 影响：可能跨租户关联、重复超额退款，退款表也无法完整关联原渠道记录。

## 当前缺失

- 原交易查询没有统一 tenantId 条件。
- 业务订单定位没有严格使用原主流水 + 原子流水。
- 第三组 `originalBizTransactionId + originalBizSubTransactionId` 尚未实现。
- 多组定位条件没有交叉校验。
- 未校验原交易存在、同银行、原交易成功、允许退款能力及原金额。
- 未计算累计退款金额，未使用行锁或等效并发控制。
- 未更新原交易 `refunded_amount`。
- 退款记录未可靠写入 `originalChannelTransactionId/originalCapability`。
- 原交易被重复查询两次用于银行请求和退款 Entity。

## 验收标准

1. 一个事务内锁定并加载同银行原 transfer/consume 记录。
2. 三组定位条件至少一组，多组必须一致。
3. 校验原交易终态及 `累计已退款 + 本次退款 <= 原金额`。
4. 银行调用确认成功后更新累计退款；未知状态按补偿流程处理，禁止直接重复退款。
5. 退款记录保存原渠道主键、能力、原流水及明确账户关联字段。
6. 中信、平安分别实现，不跨银行查表。
