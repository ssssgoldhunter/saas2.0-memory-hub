# 2026-08-17 对话记录

## Oh-DSH Desktop：modlens 视觉变体回归修复

### 问题现象

模型选择器切到「DeepSeek-V4-Flash (modlens vision)」时报：
`DeepSeek (modlens vision) 加载失败：model "deepseek-v4-flash" is outside the modlens vision wrap scope`

### 根因

1. `@oh-dsh/desktop` bundle（`~/.ohdsh/profiles/node_modules/@oh-dsh/desktop/dist/cordis.patch.yml`）
   通过 `insert` 注册 `oh-vision`（`@oh-dsh/vision` v0.1.5）。
2. `oh-vision` 的 `installDeepSeekV4ImageAdmission`（`~/.ohdsh/profiles/node_modules/@oh-dsh/vision/dist/index.js:445`）
   包装 `llm.resolveModelInfo`，对**所有 `deepseek-v4*` 模型强行注入**
   `inputModalities: [..., "image"]`（即使模型实际是 text-only）。
3. modlens 的 `resolveModel → shouldWrap()` 看到 `inputModalities.includes('image')`，
   判定"已是视觉模型，无需包装" → 抛 `outside the modlens vision wrap scope`
   （`~/.ohdsh/profiles/desktop/node_modules/@liustack/modlens/dsh/index.js:556`）。
4. 记忆体 ENVIRONMENT.md §1.4 记录的修复 = `cordis.patch.yml` 必须含
   `- id: oh-vision / disabled: true`，但该条目**已缺失**（仅剩 `dsh-obsidian-assistant`）→ 回归。

### 修复

- `~/.ohdsh/profiles/desktop/cordis.patch.yml` 恢复：

```yaml
- id: oh-vision
  disabled: true
```

- 附注释说明"必须保留"原因（对应 ENVIRONMENT.md §1.4）。
- 生效方式：patch 在 Desktop **启动时**应用，需重启 Oh-DSH Desktop。
- 副作用：`view_image` 工具消失（符合记忆体设计：视觉由 modlens 提供）。

### 待办 / 后续注意

- 重启后验证「DeepSeek-V4-Flash (modlens vision)」可正常加载。
- 日志仍见 `[modlens] paste-to-path route skipped: webserver: duplicate exact route`，
  疑似 modlens 在 dependencies 与 bundles 双重加载，不影响功能，可后续清理。
- 该 `oh-vision: disabled` 条目易丢失（本次即回归），建议 ENVIRONMENT.md §1.4 增加
  "缺失时症状" 说明，便于快速定位。
