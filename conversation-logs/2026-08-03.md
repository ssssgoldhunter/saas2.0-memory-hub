# 2026-08-03 对话记录

## SaaS 2.0 多银行渠道 Front 重构

### 本次目标

核对 `docs/saas2.0 重构` 下的现有方案是否足以让开发 AI 一次性完成除中信、平安银行协议 Handle 外的全部代码，并补充完整实施基线。

### 核对结论

- 旧 `fund-catering-front-service` 的 API → Service → Router → Handle → 钱包客户端结构可以继续参考；
- 旧项目的 BeanPostProcessor Router、旧请求对象、旧配置定位和银行对象混入 common 的方式需要优化；
- 现有 `00~03` 已覆盖总体约束和银行能力，但缺少模块/package树、类级清单、DDL、幂等、LiteFlow节点、异常收口、银行骨架、测试和验收标准；
- 补充 `04-front-service完整重构实施方案.md` 后，公共框架和中信/平安 Handle 骨架可以由开发 AI 一次实现；
- 银行请求字段、reserve映射、签名加密、bizFunc/path和响应状态仍必须逐接口确认。

### 本次固定的设计

1. 保留 api/common/service 三模块，重新限定职责；
2. Router 只按 `platformCode` 选择银行大 Handle；
3. 使用 `TransactionRouter` 和 `QueryRouter`，业务能力通过具体 Handle 方法表达；
4. 首期包含 8 个交易接口和 5 个查询接口；
5. 对外请求、响应最终调整为 `baseData + specialData` 两段式；请求 `baseData` 包含租户、门店、银行和业务强类型字段；
6. 内部通过配置端口加载 `tenantBankConfig`；
7. LiteFlow 版本跟随当前 `cateringsass` 工程 `2.12.1`，只编排公共流程；
8. 首期使用一张 `front_channel_transaction` 渠道交易流水表；
9. 中信、平安均提供 Transaction/Query Handle 骨架；
10. 未接入返回 `ADAPTER_NOT_READY`，不支持返回 `CAPABILITY_NOT_SUPPORTED`，禁止返回 `null` 或模拟成功。

## Front 公共模块合并与查询能力确认

- 工程已有 `catering-api/catering-api-front`，因此原 `catering-front-api`、`catering-front-common`
  合并到该模块，不再维护重复制品；
- `catering-front` 改为直接依赖 `catering-api-front` 和 `catering-common-core`，自身即为可运行服务，不再嵌套 `catering-front-service`；
- 对外 API、请求响应模型、常量和枚举进入 `catering-api-front`；公共返回、错误码和异常类型进入 `catering-common-core`；银行协议 DTO、运行时工具和适配实现留在 `catering-front`；
- `queryWithDrawFee()` 不再作为独立方法，由平台明细/账户交易查询按交易类型覆盖；
- `queryReceiptVerify()` 在旧实现中只有平安有真实逻辑，中信返回 `null`；其准确语义为“查询明细单验证码”，后续如纳入应使用更准确的方法名并标记为平安特有能力。
- 模块合并后按用户要求不运行验证代码，仅完成源码迁移、Maven 配置和文档的静态核对。
- 为符合现有 `catering-modules` 同级模块格式，将原 `catering-front-service/src` 上移到
  `catering-front/src`，并把启动插件和运行依赖合并到 `catering-front/pom.xml`。
- 固定后续模块职责：`catering-front` 只承载功能实现，`catering-api-front` 只承载 API 契约、
  请求响应模型、常量和枚举；公共类型统一放在 `catering-common-core`。

## 公共返回主体与错误码归属

- 所有 Front 对外 API 统一使用 `catering-common-core` 的 `R` 作为最外层返回主体；
- API 返回类型固定为 `R<FrontResponse<具体基础结果>>`，`R.data` 内继续保留
  `baseData + specialData` 两段式 Front 业务响应；
- `R.code/msg` 表达工程统一调用结果，Front 业务错误码保存在
  `R.data.baseData.frontRespCode/frontRespDesc`；
- `FrontErrorCode` 迁入 `catering-common-core/com.chinaums.common.core.error`，API 与功能模块只引用，
  不再重复定义。
- `FrontException` 迁入 `catering-common-core/com.chinaums.common.core.exception`，与
  `FrontErrorCode` 共用公共核心边界。
